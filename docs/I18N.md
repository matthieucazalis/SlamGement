# Langues (FR / EN / DE) et thème clair / sombre

## Principe

| Besoin                         | Solution                                                                                       |
| ------------------------------ | ---------------------------------------------------------------------------------------------- |
| Traduire l'interface           | Dictionnaires typés dans `src/i18n/messages/`, fonction `t("domaine.cle", { variables })`      |
| Connaître la langue d'une page | Cookie `locale` → préférence du compte → en-tête `Accept-Language` → français                  |
| Retrouver ses choix partout    | Les préférences sont aussi enregistrées sur le compte (`User.locale`, `theme`, `haptics`)      |
| Éviter l'éclair de thème clair | Classe `dark` posée côté serveur ; en mode « Système », petit script exécuté avant l'affichage |

Aucune bibliothèque externe : le besoin (3 langues, ~700 textes, pluriels simples) ne justifiait pas
`next-intl`. Le code tient en 4 fichiers courts (`config.ts`, `translate.ts`, `server.ts`, `client.tsx`).

## Utiliser une traduction

```tsx
// Composant serveur (page, action)
const t = await getT();
<h1>{t("projects.title")}</h1>;
t("projects.yourRole", { role: "Membre" }); // "Ton rôle : Membre"

// Composant client
const t = useT();
```

- **Variables** : `{nom}` dans le texte, valeur passée en second argument.
- **Pluriel** : `"{count} action|{count} actions"` ; la forme est choisie d'après `count`
  (en français 0 et 1 sont au singulier, en anglais et allemand seul 1 l'est).
- **Dates** : `formatDate(date, locale)` et `formatDateTime(date, locale)` (`lib/format.ts`),
  toujours en fuseau Europe/Paris.
- **Messages de validation** : les schémas Zod renvoient des _clés_ (`"validation.min8"`) ; les actions
  les traduisent avec `firstIssueMessage(t, erreur)`.
- **Valeurs d'énumération** (statuts, rôles) : `adrStatusLabel(t, status)`, `roleLabel(t, role)`… (`lib/labels.ts`).

## Ajouter un texte

1. Ouvrir le fichier du domaine (ex. `src/i18n/messages/adr.ts`) : les trois langues y sont côte à côte.
2. Ajouter la clé dans `fr`, puis dans `en` et `de`. Si une langue est oubliée, **le projet ne compile pas**
   (`DeepStrings<typeof fr>`), et `src/i18n/i18n.test.ts` vérifie aussi les variables `{…}` et les pluriels.

## Ajouter une langue (ex. espagnol)

1. `src/i18n/config.ts` : ajouter `"es"` à `LOCALES`, `LOCALE_NAMES` et `LOCALE_TAGS`.
2. Ajouter une propriété `es` dans chaque fichier `src/i18n/messages/*.ts` (le compilateur liste ce qui manque).
3. `translate.ts` : ajouter la règle de pluriel si elle diffère.

## Thème

| Réglage | Effet                                                                  |
| ------- | ---------------------------------------------------------------------- |
| Clair   | Aucune classe sur `<html>`                                             |
| Sombre  | `class="dark"` posée côté serveur (aucun éclair au chargement)         |
| Système | Script en tête de page + écoute du changement de réglage de l'appareil |

Les couleurs viennent de variables CSS (`globals.css`, blocs `:root` et `.dark`) ; les couleurs d'état
(erreur, succès, badges) ont leur variante `dark:`. Les schémas Mermaid prennent le thème sombre.

## Ce qui n'est volontairement pas traduit

- Le **contenu saisi par les utilisateurs** (titres d'ADR, tâches…).
- Les **statuts du fichier Markdown exporté** (`proposed`, `accepted`…) : vocabulaire standard MADR.
- La **documentation de l'API** (`/api-docs`) : documentation technique en anglais.
